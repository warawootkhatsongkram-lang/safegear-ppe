## รหัสผ่าน มี 2 ระดับ

| ระดับ | ทำอะไรได้ | แจกให้ใคร |
|---|---|---|
| **รหัสเบิก** (issue) | คีย์ใบเบิกอย่างเดียว | หัวหน้างาน / คนหน้าคลัง |
| **รหัสแม่** (admin) | ทำได้ทุกอย่าง — คลัง ประวัติ แก้รายการ | เดย์คนเดียว |

**แดชบอร์ดไม่ต้องใช้รหัสเลย** เปิดลิงก์มาเห็นกราฟทันที (ตั้งใจให้เป็นแบบนี้ — ไม่มีชื่อคนอยู่ในนั้น)

### เปลี่ยนรหัส (ทำใน Supabase → SQL Editor)

เปลี่ยน **รหัสเบิก**:
```sql
update admin_config
set issue_pin_hash = crypt('รหัสเบิกใหม่', gen_salt('bf'))
where id = 1 and pin_hash = crypt('รหัสแม่ปัจจุบัน', pin_hash);
```

เปลี่ยน **รหัสแม่**:
```sql
update admin_config
set pin_hash = crypt('รหัสแม่ใหม่', gen_salt('bf'))
where id = 1 and pin_hash = crypt('รหัสแม่ปัจจุบัน', pin_hash);
```
> ถ้าคำสั่งขึ้น `UPDATE 0` แปลว่ารหัสปัจจุบันที่ใส่ไปผิด — ยังไม่มีอะไรถูกเปลี่ยน

## เพิ่ม / แก้ รายการ PPE — ทำจากหน้าเว็บได้เลย

1. เปิดเว็บ → ใส่**รหัสแม่** → แท็บ **คลัง PPE**
2. เพิ่มของใหม่ → กดปุ่ม **＋ เพิ่มรายการใหม่**
   แก้ของเดิม → กดปุ่ม **แก้ไข** ที่แถวนั้น

### ช่องกรอกแต่ละช่อง

| ช่อง | ใส่อะไร | หมายเหตุ |
|---|---|---|
| รหัสรายการ | `a-z 0-9 _ -` เช่น `apron` | **ตั้งแล้วเปลี่ยนไม่ได้** เพราะใบเบิกเก่าอ้างถึงอยู่ |
| ชื่อรายการ | ชื่อไทยที่คนหน้างานเรียก | |
| หมวดการป้องกัน | เช่น ป้องกันมือ | ขึ้นใต้ชื่อในหน้าเบิก และเป็นป้ายในหน้า 3D |
| หน่วยนับ | ใบ / คู่ / อัน / ชิ้น / ตัว | |
| ขั้นต่ำ | ต่ำกว่านี้ระบบขึ้นเตือน "ต่ำกว่าขั้นต่ำ" | ใกล้หมด = ไม่เกินขั้นต่ำ × 1.2 |
| ยอดเป้าหมาย | ยอดที่อยากให้มีในคลัง | ใช้อ้างอิงตอนสั่งซื้อ |
| สี | รหัส HEX 6 หลัก | ใช้เป็นสีแท่งกราฟ + สีชิ้นงานในหน้า 3D |
| รูปทรงในหน้า 3D | เลือกจาก 7 แบบ | เลือกอันที่หน้าตาใกล้ที่สุด |
| วันหมดอายุ / เปลี่ยนล่าสุด | `ปีค.ศ.-เดือน` เช่น `2027-06` | **เว้นว่างได้** ถ้าของไม่มีวันหมดอายุ |
| รอบเปลี่ยน | จำนวนเดือน | |
| ลำดับที่แสดง | เลขน้อยขึ้นก่อน | |

### ⚠️ 3 เรื่องที่ต้องรู้

1. **หน้านี้ไม่แตะจำนวนคงเหลือ** — ของใหม่เริ่มที่ **0** เสมอ
   บันทึกเสร็จให้กด **ปรับยอด → รับของเข้า** เพื่อใส่จำนวนจริง
   (ทำแบบนี้เพราะทุกยอดต้องมีที่มาใน audit trail ไม่งั้นสต็อกกับประวัติจะไม่ตรงกัน)
2. **การแก้รายการไม่ถูกบันทึกลง audit trail** — audit trail บันทึกเฉพาะการเคลื่อนไหวของ*จำนวน*
3. **"ซ่อนรายการ" เอากลับเองจากหน้าเว็บไม่ได้** — วิธีเอากลับอยู่หัวข้อถัดไป

### เอารายการที่ซ่อนไว้กลับมา

```sql
-- ดูว่าซ่อนอะไรไว้บ้าง
select id, name from ppe_items where not active;

-- เอากลับมา (แทน 'apron' ด้วยรหัสรายการจริง)
update ppe_items set active = true, updated_at = now() where id = 'apron';
```
> ของที่ซ่อนไม่ได้ถูกลบ — ประวัติใบเบิกเก่ายังอ้างถึงได้ครบ นี่คือเหตุผลที่ระบบซ่อนแทนลบ

## แก้ข้อความในระบบ

เปิด `index.html` ด้วย Notepad หรือ VS Code แล้ว **กด Ctrl+F ค้นข้อความที่จะแก้** ได้เลย
ไฟล์แบ่งเป็น 9 ส่วน มีหัวข้อคั่นชัดเจน (`1) CONFIG`, `2) STATE`, ... `9) TEST SUITE`)

จุดที่แก้บ่อย ค้นด้วยคำนี้:

| อยากแก้ | ค้นคำว่า | อยู่ส่วน |
|---|---|---|
| ชื่อผู้จ่ายในเอกสาร (`จป.วิชาชีพ`) | `APPROVER_DEFAULT` | 1) CONFIG |
| ชื่อ/คำอธิบาย/ไอคอนของ 4 แท็บ | `const TABS` | 1) CONFIG |
| เตือนใกล้หมดอายุกี่เดือน (ตอนนี้ 3) | `EXPIRY_WARN_M` | 4) LOGIC |
| ชื่อระบบบนหัวเว็บ | `SafeGear` | หลายที่ — แก้ให้ครบทุกที่ |
| ข้อความท้ายเอกสารที่พิมพ์ | `เอกสารนี้ออกจากระบบ` | 6) RENDER |
| คำในขั้นตอนเบิก 3 ขั้น | `เลือกรายการ` | 6) RENDER |
| เกณฑ์สถานะสต็อก (หมด/ใกล้หมด) | `function statusOf` | 4) LOGIC |

**กฎเหล็กเวลาแก้เอง:**
- ก๊อปไฟล์เก็บไว้ก่อนเสมอ (ลากใส่โฟลเดอร์ `เก็บของ\`)
- แก้แต่**ข้อความในเครื่องหมายคำพูด** อย่าลบเครื่องหมาย `'` `"` `` ` `` `<` `>` `{` `}`
- แก้เสร็จเปิด `index.html?test=1` **ต้องขึ้น ✓ ผ่านทั้งหมด** ถ้าตัวเลขไม่ครบหรือขึ้นแดง = แก้พลาด ให้เอาไฟล์สำรองกลับมา

## เครื่องมือตรวจระบบ

| ใส่ท้าย URL | ได้อะไร |
|---|---|
| `?test=1` | รันชุดทดสอบทั้งหมด — ต้องขึ้น **✓ ผ่านทั้งหมด** |
| `?debug=1` | เปิดแผงดีบักมุมขวาล่าง เห็นค่าจริงทุกตัวขณะทำงาน |

แผงดีบักซ่อนไว้โดยตั้งใจ คนหน้างานไม่เห็น แต่เดย์เรียกดูได้ทุกเมื่อ
**เวลาระบบมีปัญหา: เปิด `?debug=1` แล้วถ่ายรูปแผงนั้นส่งมา** จะหาสาเหตุได้เร็วกว่าเดาเยอะ

ตรวจว่าสต็อกตรงกับ audit trail (รันใน Supabase → SQL Editor):
```sql
select * from stock_reconciliation;
```

## อัปเดตเว็บขึ้น GitHub Pages

เครื่องเดย์**ไม่ได้ติดตั้ง Git** — อัปเดตด้วยการลากไฟล์ผ่านหน้าเว็บ GitHub ได้เลย ไม่ต้องลงโปรแกรมอะไร:

1. เปิด https://github.com/warawootkhatsongkram-lang/safegear-ppe
2. กด **Add file → Upload files**
3. **ลากไฟล์ที่แก้แล้วจากโฟลเดอร์ในเครื่อง** ใส่กรอบ (ชื่อไฟล์ต้องตรงกับของเดิมเป๊ะๆ ระบบจะทับให้เอง)
4. ช่องล่างพิมพ์สั้นๆ ว่าแก้อะไร → กด **Commit changes**
5. รอ 1–2 นาที เว็บอัปเดตเอง

ถ้าเปิดแล้วยังเห็นของเก่า → กด `Ctrl + Shift + R` (โหลดใหม่แบบไม่ใช้แคช)

> **ย้อนกลับเวอร์ชันเก่าได้**: ในหน้า repo กดที่ไฟล์ → ปุ่ม **History** → เลือกเวอร์ชันก่อนหน้า → กด **View file** แล้วโหลดกลับมาใช้
> GitHub เก็บทุกเวอร์ชันให้อัตโนมัติทุกครั้งที่อัปโหลด นี่คือ undo ของโปรเจคนี้

## เวลามีปัญหา ไล่ตามลำดับนี้

| อาการ | ตรวจอะไรก่อน |
|---|---|
| แดชบอร์ดขึ้น "ยังโหลดตัวเลขไม่สำเร็จ" | รัน `▶ schema.sql` ครบหรือยัง (รันซ้ำได้ปลอดภัย ข้อมูลไม่หาย) |
| ใส่รหัสแล้วขึ้น "รหัสไม่ถูกต้อง" | รหัสถูกเปลี่ยนไปหรือเปล่า · ลองรหัสแม่ดู |
| หน้าเบิกไม่มีรายการเลย | รายการถูกซ่อนหมดหรือเปล่า → `select id,name,active from ppe_items;` |
| สต็อกไม่ตรงกับของจริงบนชั้น | `select * from stock_reconciliation;` แล้วปรับยอดผ่านหน้าคลัง (มีที่มาใน audit trail) |
| หน้า 3D ช้า/ร้อนบนมือถือ | เปิด `story.html?debug=1` ดูบรรทัด fps / tier |
